## 根因
真实 `huggingface_hub.HfApi.list_repo_tree` 用法为：
`list_repo_tree(repo_id, *, path_in_repo=..., repo_type=..., recursive=True)`。
测试替身先前错误写成 `list_repo_tree(self, repo_type=None, path_in_repo=None, **kwargs)`，没有给第一个位置参数 `repo_id` 预留位置，导致参数绑定冲突。它属于**测试替身实现错误**，不是数据集、GPU或论文方案失败。

## 修复
更新为 `list_repo_tree(self, repo_id, repo_type=None, path_in_repo=None, **kwargs)`，加入 `repo_id` 属于 RoboReel 官方模型/数据仓库以及 `recursive=True` 的检查；真实生产调用不变。
